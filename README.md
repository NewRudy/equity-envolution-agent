# 股权估值工作台

面向股权投资预审的精简工作台：导入目标公司财务数据，人工审阅 3–8 家可比公司，计算 EV/EBITDA 或 P/B 市场法，并把 DCF 作为独立敏感性参照。结果和关键来源可下载为 Excel 底稿。

本项目不自动抓取行情、不自动挑选同行、不生成投资建议，也不替代专业估值人员。

## 一次分析怎么走

首页提供“先看完整示例”和“开始我的估值”。完整示例使用虚构的公司与行情，底稿会明确标记复核条件为演示预设，不会冒充真实人工复核。

1. 公司数据：填写名称，下载空白模板并上传财务表；列名应标注金额单位。
2. 可比公司：上传表格或逐家录入；核对公司数据、来源、报告期、取价依据和理由，选择 3–8 家。可点击“所选公司采用等权重”，也可自己分配权重。
3. 确认计算：填写复核人，完成四项口径确认。折扣、其他股权调整和 DCF 均收进选做区域；DCF 默认不计算。
4. 分析结果：先看股权价值与样本观察范围，再展开计算和来源，下载 Excel 底稿。

页面固定为浅色主题，主要文字与输入标签使用 18px；每次只展示当前步骤。可比公司采用逐家编辑，修改记录在当前会话中；切换方法、上传新表、调整权重或数据后会清除旧确认，要求重新复核。

空白财务模板含营业收入、EBITDA、净债务、账面权益、现金流等字段，不夹带合成数值。P/B 法须有目标账面权益和明确的归母/合并口径。演示开关提供的财务数据为合成样例，不是市场数据。

## 市场法输入与公式

可比公司表字段见页面下载的模板。股权市值、净债务、其他 EV 调整、EBITDA、账面权益均按人民币亿元填写。净现金用负数表示净债务。每家纳入公司必须填写可回查的数据来源、报告期、取价依据、入选理由、修正理由和正权重；权重合计必须为 100%，纳入 3–8 家。

- EV/EBITDA：可比 EV = 股权市值 + 净债务 + 其他 EV 调整；可比倍数 = EV / EBITDA。
- P/B：可比倍数 = 股权市值 / 账面权益；可比公司的账面权益口径须填写。
- 先将每家可比公司的原始倍数乘以修正系数，再按人工权重加权。
- EV/EBITDA 目标股权价值 = (目标 EBITDA × 加权修正倍数 - 目标净债务) × (1 - 流动性折扣) + 其他股权价值调整。
- P/B 目标股权价值 = 目标账面权益 × 加权修正倍数 × (1 - 流动性折扣) + 其他股权价值调整。

其他 EV 调整用于少数股东权益、优先股或其他融资项目；无调整时也须明确填 0。目标公司有额外股权桥接项目时，在其他股权价值调整中填写，并提供理由和依据。流动性折扣非零时也必须提供理由和来源。页面低/高值是所选样本的修正倍数观察范围，不是统计置信区间。

检测到未标单位、重复年度、关键数据缺失，或缺少来源、复核与口径确认时，市场法不输出目标估值。空值不会自动按零处理。

## 本地运行

环境要求：Python 3.12。

创建虚拟环境并安装 requirements.txt 后运行：

    streamlit run app.py

页面默认不载入企业数据。点击首页“先看完整示例”即可查看一份完整的合成结果；真实项目通过“开始我的估值”创建，示例数据不会混入新项目。

界面回归检查：

    python -m unittest discover -s tests -v

## 部署

生产服务使用 systemd 和现有 Caddy 反向代理，监听本机 Docker 网关的 8501 端口，公网路径为：

    https://rudy.cc.cd/equity_envolution/

服务器代码目录为 /opt/equity-envolution-agent，服务名为 equity-envolution-agent.service。更新时先备份当前版本，再同步代码、安装依赖并重启 systemd 服务；确认 Streamlit 健康端点和公网子路径后再结束部署。APP_PASSWORD 及其他运行配置仅存放于服务器的 root-only 环境文件，不得提交到仓库。

本地 Docker Compose 默认绑定 127.0.0.1:8501，适用于开发或 SSH 隧道，不负责生产 Caddy 子路径。

## 来源与产品判断

本版本吸收了伙伴仓库中值得保留的业务原则：人选择可比公司并承担确认责任；报告期、取价依据、来源、净债务桥接、修正和权重显式记录；数据与计算公式可以回查；未确认的数据不强行闭环。

伙伴仓库中的预填答案、硬编码历史结果、未完成的底稿渲染和跨模块假闭环不作为本产品输入。仓库未提供的真实目标公司数据或市场行情不会被补造。产品目前聚焦于一家公司、两种市场法、一个 DCF 参照和一份工作底稿。
